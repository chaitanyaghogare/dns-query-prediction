Limitations
    
      
  • Evaluation is trace replay in a simulator, not a production resolver; upstream latency is modelled, not measured.
    • 
      
  • The default dataset is synthetic. Its page-load structure is cleaner than real traffic, so gains are likely optimistic.
    • 
      
  • Prefetching costs extra upstream queries; the threshold trades hit rate against that cost.
    • 
      
  • The follow-up model only knows pairs seen at least 5 times in training; new sites get no prediction.
    • 
      
  • Refresh decisions change future data (policy shift); two DAgger-style retraining rounds reduce, not remove, this.
    • 
    

    
Future work
    
      
  • Run the same pipeline on a real capture (the tshark adapter is ready).
    • 
      
  • Per-client follow-up models, and prefetch only when the upstream is idle.
    • 
      
  • Adapt the threshold online from the measured prefetch precision.
    • 
      
  • Deploy the logging forwarder on a lab network and compare live numbers with the simulator.
